# Sources Parser in the Research Crate Implementation Plan

## Overview

Add the first Rust reading of the Sources grammar to the `research` crate:
a **tier-text parser** (`TierText::parse`) and a **Sources parser**
(`SourcesSection::parse`) that reads a document body's `## Sources` section
into cited sources, unread lines, a section state and a line span, with
`LineSpan::split` to cut the body around the section and
`LineSpan::remove_from` to drop the section from it. Both live in
`research::topic::sources_section` and are pure, hand-written `str` parsers.

The work lands as four phases. Each phase is test-first, adds only public
items, regenerates the public-API snapshot, and leaves `mise run` green, so
each can merge on its own.

## Current State Analysis

- No Rust code parses Sources or tier text. The crate has `enum Tier { One,
  Two, Three }` with `Display` only (`cli/research/src/sources/record.rs:9-24`)
  and `Record` with separate `retracted`/`withdrawn` booleans
  (`record.rs:48-60`). Both stay unchanged.
- The grammar is defined in `skills/research/outputters/citing-once/SKILL.md`
  (`:25-30`, `:64-82`, worked example `:158-181`) and
  `skills/research/outputters/finding-outputter/SKILL.md:80-154`. PP-995's
  line rules are the only definition of section bounds, line endings, blank
  lines and `None found.` beside entries.
- The Python reference (`tasks/eval/documents/sources.py`) is looser and fails
  where PP-995 reports; it is not an oracle for rejection and stays untouched.
- `research` may import only std, `kernel::Error`, `network` and itself
  (`cli/pup.ron:95-114`); its manifest has `network` only and no
  dev-dependencies. No `regex`, no serde.
- The workspace is edition 2021 (`cli/Cargo.toml:58`), so no let-chains.
  Clippy pedantic + nursery with `unwrap_used`/`expect_used`/`panic` warn.
- The public API of `research` is pinned in
  `cli/research/tests/fixtures/public-api.txt` and checked by
  `mise run public-api:check` (part of `mise run check`); regenerated by
  `mise run public-api:update`.

## Desired End State

- `research::topic::sources_section` exports `SourcesSection`, `CitedSource`,
  `TierReading`, `MetadataPair`, `UnreadLine`, `LineSpan`, and the submodule
  `tier_text` exporting `TierText` and `NotTierText`.
- `cli/research/tests/tier_text.rs` and `cli/research/tests/sources_section.rs`
  cover every acceptance criterion of PP-995 against public exports only.
- The public-API snapshot diff against the pre-plan file holds additions only;
  the `Tier` and `Record` lines are byte-identical.
- `cli/research/Cargo.toml` is unchanged; no crate gains a dependency edge.
- `mise run` exits 0.

### Key Discoveries:

- `Outline::parse` (`cli/research/src/topic/outline.rs:28-41`) is the house
  shape for an infallible whole-document line parser with 1-based numbers.
- `Stem` keeps the round-trip contract `parse(s)?.to_string() == s`
  (`cli/research/src/topic/layout/stem.rs:21`, test `:119-127`). `TierText`
  meets it by canonical rendering: strict shape means only canonical text is
  accepted.
- `StoredCount::Unreadable(String)` (`cli/research/src/topic/counts.rs:81-86`)
  is the precedent for `TierReading::Rejected(String)`.
- The `refused` closure (`cli/shortcut-client/src/shortcut_key.rs:71-105`)
  is the idiom for an error that always carries the whole input.
- Tests in `cli/research/tests/` are behavioural sentences with table loops
  and the input as the assertion message (`tests/metadata_date.rs:13-36`);
  `#![allow(clippy::expect_used)]` where needed.
- `str::lines()` drops a second `\r` on `\r\r\n` and `split('\n')` yields a
  phantom last line, so the line rule is `split_inclusive('\n')`, strip `\n`,
  then at most one `\r`.
- Imports are one item per `use` line (`cli/pup.ron:598-602`).

## What We're NOT Doing

- No change to the Python eval parser or its tests, and no porting of its
  test cases.
- No change to the citing-once or finding-outputter skills, nor to their
  wording drift (finding-outputter `:96-97`).
- No visualiser change, no server dependency on `research` (PP-1002 adds it),
  no wire shape (PP-1000 decides it), no serde derives.
- No change to `Tier`, `Record` or `sources::tier`.
- No `FromStr` impls; parsers are inherent `parse` methods.
- No enforcement of the citing-once rule's constraints (merge order, distinct
  `also` tiers, retraction implying tier-3); shape only.
- No frontmatter awareness: line numbers count lines of the string given.

## Implementation Approach

Module layout:

```
cli/research/src/topic.rs                          + pub mod sources_section;
cli/research/src/topic/sources_section.rs          SourcesSection, CitedSource, TierReading,
                                                   MetadataPair, UnreadLine, LineSpan
cli/research/src/topic/sources_section/tier_text.rs TierText, NotTierText
cli/research/src/topic/sources_section/lines.rs     private line rule
```

Every new public type derives `Debug, Clone, PartialEq, Eq` (plus `Copy` on
`LineSpan`) and nothing else, to keep the snapshot additions to what callers
need. Fields are public on plain data (`CitedSource`, `MetadataPair`,
`UnreadLine`), matching `Outline`/`Pair`; fields are private behind getters
where the value must come from a parse (`TierText`, `LineSpan`).

Each phase follows red-green-refactor: write the phase's integration tests
first and see them fail (a compile failure against a not-yet-existing type
is the first red; then stub the signatures so each test fails on its
assertion), implement to green, refactor, then `mise run public-api:update`
and inspect the diff.

`tier_text` imports `crate::sources::record::Tier`, the first edge from
`topic` into `sources`. `Tier` is the shared base-tier vocabulary, and the
edge runs one way only: nothing in `sources` imports from `topic`. Base tiers
are read by matching `Tier`'s own `Display`, so the tier labels stay defined
once, in `record.rs`.

`topic.rs`'s module doc gains a clause naming the Sources section a finding or
note carries, so the module doc still describes what `topic` holds.

```rust
//! Tier text: a base tier with its retraction marks and `also` tiers.

use std::fmt;

use crate::sources::record::Tier;

const RETRACTED: &str = "retracted";
const WITHDRAWN: &str = "withdrawn";
const ALSO: &str = "also ";
const PART_SEPARATOR: &str = "; ";
const ALSO_SEPARATOR: &str = ", ";
const BASE_TIERS: [Tier; 3] = [Tier::One, Tier::Two, Tier::Three];

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct TierText {
    base: Tier,
    retracted: bool,
    withdrawn: bool,
    also: Vec<Tier>,
}

impl TierText {
    /// Checks shape only, so `parse(s)?.to_string() == s`.
    ///
    /// # Errors
    ///
    /// [`NotTierText`], carrying the whole input, for text not of tier-text
    /// shape.
    pub fn parse(text: &str) -> Result<Self, NotTierText> {
        let refused = || NotTierText(text.to_owned());
        let Some((base_text, suffix)) = text.split_once(' ') else {
            return base_tier(text).map(Self::bare).ok_or_else(refused);
        };
        let base = base_tier(base_text).ok_or_else(refused)?;
        let parenthesised = suffix
            .strip_prefix('(')
            .and_then(|inner| inner.strip_suffix(')'))
            .ok_or_else(refused)?;
        Self::with_parts_in_canonical_order(base, parenthesised)
            .ok_or_else(refused)
    }

    const fn bare(base: Tier) -> Self {
        Self {
            base,
            retracted: false,
            withdrawn: false,
            also: Vec::new(),
        }
    }

    fn with_parts_in_canonical_order(
        base: Tier,
        parenthesised: &str,
    ) -> Option<Self> {
        let mut parts = parenthesised.split(PART_SEPARATOR).peekable();
        let retracted = parts.next_if_eq(&RETRACTED).is_some();
        let withdrawn = parts.next_if_eq(&WITHDRAWN).is_some();
        let also = match parts.next() {
            Some(part) => also_tiers(part)?,
            None => Vec::new(),
        };
        parts.next().is_none().then_some(Self {
            base,
            retracted,
            withdrawn,
            also,
        })
    }

    #[must_use] pub const fn base(&self) -> Tier { self.base }
    #[must_use] pub const fn retracted(&self) -> bool { self.retracted }
    #[must_use] pub const fn withdrawn(&self) -> bool { self.withdrawn }
    #[must_use] pub fn also(&self) -> &[Tier] { &self.also }
}

fn base_tier(text: &str) -> Option<Tier> {
    BASE_TIERS.into_iter().find(|tier| tier.to_string() == text)
}

fn also_tiers(part: &str) -> Option<Vec<Tier>> {
    part.strip_prefix(ALSO)?
        .split(ALSO_SEPARATOR)
        .map(base_tier)
        .collect()
}

impl fmt::Display for TierText {
    fn fmt(&self, formatter: &mut fmt::Formatter<'_>) -> fmt::Result {
        let also = (!self.also.is_empty()).then(|| {
            let tiers: Vec<String> =
                self.also.iter().map(Tier::to_string).collect();
            format!("{ALSO}{}", tiers.join(ALSO_SEPARATOR))
        });
        let parts: Vec<String> = [
            self.retracted.then(|| RETRACTED.to_owned()),
            self.withdrawn.then(|| WITHDRAWN.to_owned()),
            also,
        ]
        .into_iter()
        .flatten()
        .collect();
        write!(formatter, "{}", self.base)?;
        if parts.is_empty() {
            return Ok(());
        }
        write!(formatter, " ({})", parts.join(PART_SEPARATOR))
    }
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct NotTierText(String);

impl NotTierText {
    #[must_use] pub fn text(&self) -> &str { &self.0 }
    #[must_use] pub fn into_text(self) -> String { self.0 }
}

impl fmt::Display for NotTierText {
    fn fmt(&self, formatter: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(formatter, "not tier text: `{}`", self.0)
    }
}

impl std::error::Error for NotTierText {}
```

`with_parts_in_canonical_order` is a sequence of shape checks: an empty `()`
reaches `also_tiers("")` and fails; an out-of-order or repeated mark falls
through to `also_tiers` and fails; any part after the `also` list fails. Only the canonical form survives,
which is why `Display` from the parts reproduces the input.

#### 2. The line rule

**File**: `cli/research/src/topic/sources_section/lines.rs` (new, private)

```rust
//! The one rule for what a line of a document body is.

pub struct Line<'body> {
    pub number: usize,
    pub text: &'body str,
}

pub fn numbered(body: &str) -> impl Iterator<Item = Line<'_>> {
    body.split_inclusive('\n').zip(1..).map(|(as_written, number)| {
        let text = as_written.strip_suffix('\n').unwrap_or(as_written);
        let text = text.strip_suffix('\r').unwrap_or(text);
        Line { number, text }
    })
}
```

Items are plain `pub`: the private `mod lines;` confines them, and
`pub(crate)` inside a private module trips nursery's `redundant_pub_crate`.
Phase 4 adds `offset_of` here, so the line rule's byte extents stay in this
module too.

#### 3. The section types and parser

**File**: `cli/research/src/topic/sources_section.rs`

```rust
const SOURCES_HEADING: &str = "## Sources";
const LEVEL_TWO_HEADING: &str = "## ";
const NONE_FOUND: &str = "None found.";
const ENTRY_OPENING: &str = "- [";
const TITLE_CLOSE: &str = "](";
const SEGMENT_SEPARATOR: &str = " — ";

/// Lines are numbered from 1 within the text parsed, frontmatter or not.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum SourcesSection {
    Absent,
    DeclaredEmpty { span: LineSpan, unread: Vec<UnreadLine> },
    Present { span: LineSpan, entries: Vec<CitedSource>, unread: Vec<UnreadLine> },
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct CitedSource {
    pub title: String,
    pub url: String,
    pub tier: TierReading,
    pub venue: Option<String>,
    pub metadata: Vec<MetadataPair>,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct MetadataPair {
    pub key: String,
    pub value: String,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum TierReading {
    Parsed(TierText),
    Rejected(String),
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct UnreadLine {
    pub line: usize,
    pub text: String,
}

/// From the heading's line up to, not including, `end`, the first line after
/// the section.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct LineSpan {
    start: usize,
    end: usize,
}

impl LineSpan {
    #[must_use] pub const fn start(self) -> usize { self.start }
    #[must_use] pub const fn end(self) -> usize { self.end }
}
```

`SourcesSection` gains `entries(&self) -> &[CitedSource]`,
`unread(&self) -> &[UnreadLine]` and `span(&self) -> Option<LineSpan>`,
written as the tests first call them.

Parsing:

```rust
impl SourcesSection {
    #[must_use]
    pub fn parse(body: &str) -> Self {
        let mut lines = lines::numbered(body);
        let Some(heading) = lines.find(|line| line.text == SOURCES_HEADING)
        else {
            return Self::Absent;
        };
        let mut reading = SectionReading::opened_at(heading.number);
        lines
            .take_while(|line| !line.text.starts_with(LEVEL_TWO_HEADING))
            .for_each(|line| reading.read(&line));
        reading.closed()
    }
}
```

Lines are consecutive, so the span's end is the last line read plus one,
which is the closing heading's number or the line count plus one at the end
of the body. `SectionReading` (private) holds `start`, `last`, `entries`,
`unread` and `declares_none_found`. `opened_at(start)` sets `last` to
`start`, so a heading with nothing under it spans `start..start + 1`. `read`
sets `last` to the line's number
before classifying it, for every line including ignored ones, so trailing
blank lines stay inside the span:

- whitespace-only line → ignored;
- exactly `None found.` → sets `declares_none_found`;
- `CitedSource::parse(text)` is `Some` → pushed;
- otherwise → `UnreadLine { line, text }`.

`closed()` returns `DeclaredEmpty` when there are no entries and `None found.`
was seen, otherwise `Present`.

`CitedSource::parse` (private, `fn parse(line: &str) -> Option<Self>`):

```rust
let rest = line.strip_prefix(ENTRY_OPENING)?;
rest.rmatch_indices(TITLE_CLOSE).find_map(|(close, _)| {
    let title = &rest[..close];
    let link_and_rest = &rest[close + TITLE_CLOSE.len()..];
    Self::entry_after_title(title, link_and_rest)
})
```

`entry_after_title(title, link_and_rest)` requires a non-empty title, then
reads each token rule through its own small function: `url_and_rest` takes
the URL up to the first `)`, requiring it non-empty and free of whitespace;
`tier_and_venue` requires the rest after `)` to start with ` — ` followed by
at least one character and splits that text at the first ` — ` into tier
text and venue, a venue of `""` being `None`. The tier is read by the private
`TierReading::of(tier_text)`, where `Parsed` holds `TierText::parse`'s value
and `Rejected` holds `NotTierText::into_text()`; it is an associated function,
not a `From` impl, so the public surface keeps `TierText::parse` as the one
way to read tier text. `metadata` starts empty.

Trying `](` from the right is the title rule as the work item states it: the
title ends at the last `](` for which the rest of the line still reads as an
entry. A venue ending in a markdown link followed by ` — ` and more text
places the title's end inside the venue, which the rule accepts as written;
`the_title_ends_at_the_last_link_close_that_still_reads_as_an_entry` pins
that direction.

#### 2. Implementation

**File**: `cli/research/src/topic/sources_section.rs`

```rust
impl LineSpan {
    /// `body` must be the text the span was read from.
    #[must_use]
    pub fn split(self, body: &str) -> (&str, &str) {
        let before = &body[..lines::offset_of(body, self.start)];
        let after = &body[lines::offset_of(body, self.end)..];
        (before, after)
    }

    /// `body` must be the text the span was read from.
    #[must_use]
    pub fn remove_from(self, body: &str) -> String {
        let (before, after) = self.split(body);
        [before, after].concat()
    }
}
```

**File**: `cli/research/src/topic/sources_section/lines.rs`

```rust
pub fn offset_of(body: &str, number: usize) -> usize {
    body.split_inclusive('\n')
        .take(number.saturating_sub(1))
        .map(str::len)
        .sum()
}
```

`offset_of` is the byte offset where line `number` starts, measured over the
same `split_inclusive('\n')` pieces `numbered` reads. A line number past the
last line gives the body's length, so a span running to the end leaves an empty
after-text. Every offset falls just after a `\n` or at either end of the
body, so both slices sit on character boundaries.
