## Inline Comments

### `src/order_total.py:13` — Order total ignores line-item quantity
**Severity**: critical | **Confidence**: high | **Lens**: correctness

🔴 **Correctness**

The loop adds `item.price` once per line item, so an order of three widgets at
10.00 totals 10.00 instead of 30.00.

**Impact**: Every multi-quantity order is undercharged.

**Suggestion**: Accumulate `item.price * item.quantity`.

---

### `src/order_total.py:14` — Bulk discount threshold and rate are magic numbers
**Severity**: major | **Confidence**: high | **Lens**: code-quality

🟡 **Code Quality**

`100` and `0.9` encode a business rule (10% off orders over 100) with no name.

**Impact**: The rule is hard to find and easy to change inconsistently.

**Suggestion**: Extract `BULK_DISCOUNT_THRESHOLD = 100` and
`BULK_DISCOUNT_RATE = 0.10` as named module constants.

---

### `src/order_total.py:10` — Function name `calc` does not describe what it calculates
**Severity**: minor | **Confidence**: medium | **Lens**: standards

🔵 **Standards**

`calc` gives no hint that it returns an order total.

**Impact**: Call sites read poorly and the function is hard to search for.

**Suggestion**: Rename to `order_total`.

---

### `src/order_total.py:21` — Removed `round_cents` used float rounding
**Severity**: suggestion | **Confidence**: low | **Lens**: code-quality

🔵 **Code Quality**

The old `round_cents` helper rounded with `round(value, 2)`, which mis-rounds
some half-cent values in binary floating point.

**Impact**: Totals could be off by a cent.

**Suggestion**: Use `decimal.Decimal` with `ROUND_HALF_UP` for currency
rounding.
